jax do not support naive self parameters

Yes, it is possible to JIT-compile class methods with JAX, but you’re right to be cautious: naïvely using self with @jit can cause issues if you’re not careful about what is traced and what is static.

Below is a clear mental model and a few safe patterns, especially relevant given your work with Kalman filters and structured models.

Why self can be problematic

jax.jit traces functions, not objects.
If a method captures self, JAX will try to trace the entire object, which fails when self contains:

Python objects

mutable state

non-JAX arrays

functions, classes, or config flags

So the rule of thumb is:

Only JAX arrays and PyTrees should be traced. Everything else must be static.

✅ Recommended patterns
Pattern 1: Make the class a PyTree (best practice)

If your class mostly stores parameters (arrays, scalars), register it as a PyTree.

from dataclasses import dataclass
import jax
import jax.numpy as jnp
from jax.tree_util import register_pytree_node_class

@register_pytree_node_class
@dataclass
class Model:
    A: jnp.ndarray
    Q: jnp.ndarray

    def tree_flatten(self):
        children = (self.A, self.Q)
        aux_data = None
        return children, aux_data

    @classmethod
    def tree_unflatten(cls, aux_data, children):
        A, Q = children
        return cls(A, Q)

    @jax.jit
    def step(self, x):
        return self.A @ x + jnp.diag(self.Q)


✔ self is now traceable
✔ Clean, composable, works with grad, jit, vmap

Pattern 2: JIT a pure function, keep the class thin (very robust)

This is often the cleanest approach.

@jax.jit
def step_fn(A, Q, x):
    return A @ x + jnp.diag(Q)

class Model:
    def __init__(self, A, Q):
        self.A = A
        self.Q = Q

    def step(self, x):
        return step_fn(self.A, self.Q, x)


✔ No tracing of self
✔ Easiest to debug
✔ Very common in JAX codebases

Pattern 3: Use static_argnums for non-array attributes

If self contains configuration options:

class Model:
    def __init__(self, A, order):
        self.A = A
        self.order = order  # static

    def step(self, x):
        return self._step(self.A, x, self.order)

    @jax.jit(static_argnums=2)
    def _step(A, x, order):
        return A @ x + order


⚠️ Recompiles when order changes
⚠️ Less clean than Pattern 2

🚫 What not to do
class Bad:
    @jax.jit
    def step(self, x):
        self.counter += 1   # ❌ mutation
        return self.A @ x


Mutation breaks JAX’s functional model

Python side effects are ignored or cause errors

Practical advice (based on your work)

Given your Kalman filter + EM + sparse algebra setup:

Keep state outside the class

Use classes as containers, not logic

JIT pure update functions

Pass matrices explicitly (even if verbose)

This will also make grad, hessian, and vmap far more reliable.
